## 3. Concrete policy interface and stall behavior

Use **Discrete(1501)** shared tokens: 0..1499 are cell indices `x+50*y` in cell stages; 1500 is CANCEL in operand stages. At ROOT, tokens 0..9 denote the ten controls in the table in order. In direction stages only tokens 0..7 mean the host's exact direction order. In offer stage only 0/1 plus cancel are syntactically eligible. All unused tokens are invalid interface syntax, not strategic pruning. Stages: ROOT, CELL_FIRST, DIRECTION, OBJECT_CELL, CELL_SECOND, OFFER. Root-control identity and operands disambiguate shared tokens. New/edit motorway uses FIRST then SECOND; edit's initial OBJECT_CELL selects the object. A roundabout/remove tile uses CELL_FIRST then commits. Removing an object uses OBJECT_CELL then commits. Cancel drops operands and returns ROOT with no world edit; it cannot consume or refund stock. Every token is one PPO environment decision; a complete semantic edit can require multiple tokens. It has no game-time cost. This fits the library's supported discrete mask interface while avoiding millions of endpoint-pair logits [S2].

No explicit house-destination goal hierarchy, separate strategic model or auto-completion policy in v1. One policy chooses sequential edits from visible state. Rationale: fewer unvalidated components and transparent compliance with the route ban; not a claim local control is easiest to learn.

**Operational stall guard:** at 4,096 policy tokens without any positive game-time advance, interrupt with `truncated=True`, `terminal_observation` of the still-live state, reason `paused_policy_stall`. Count operand/cancel/no-op tokens too. No forced wait, reward penalty or extra physical mask. Counter is observable, resets only after positive time advance and is logged. This bounds compute, not an assertion that 4,096 edits are illegal. In evaluation this is an incomplete/invalid-for-competition episode: preserve score-to-date and replay, report completion rate and diagnostic all-attempt score; never quietly drop it or call it completed. Any stall disqualifies the current checkpoint from competition claims. For training bootstrap as an external interruption [S3]. Numerical guard is a conservative engineering limit, not empirically optimal.

## 4. Exact visible-state input schema

Structured float32 Dict: `grid` **(81,30,50)**, `global` **(54,)**, `motorways` **(1500,6)**. Arrays use y,x order; no city ID, seed, future schedule or RNG fields. Visibility gate every spatial feature before aggregation. This is a partial observation model, not a claim of full Markov state or identical human perception. The remaining-time feature defines a fair finite benchmark; exact continuous hidden overcrowding timer is excluded. Demand pins/upgraded appearance are visible; pressure is a coarse visible icon state (0 normal,1 warning), not raw OvercrowdedFor. The accepted TrafficViewer.cs line258 draws an overload bar when OvercrowdedFor>0: use only the displayed-bar presence as warning1, never the raw timer or debug inspector text.

**24 history channels:** four frames, six fields each: vehicle occupancy `n/(n+1)`, mean visible heading x/y, mean observed velocity x/y transformed as `v/(abs(v)+4)`, and fraction of tracked cars with movement below .02 tiles/s. Rasterize by floor(position+.5) clipped to valid visible canvas; aggregate all visible cars, with zero for empty cells. Derive velocity from matched visible car IDs and positions across distinct simulation timestamps, never internal route/speed/wait/obstacle fields. First observation has only current occupancy/heading, zero velocity/stopped estimates and a missing-history flag. Retain the four most recent distinct-time observation frames, newest first. Wait usually samples at one second; early weekly returns sample at actual elapsed ticks. Paused edits update static channels but neither duplicate nor advance history. Reuse prior frame estimates until actual new motion is observed. History ages and validity explicitly disambiguate missing frames.

**54 global values**, in order: inventory6 `n/(n+100)`; two offer descriptors each `[present,type one-hot6,amount/(amount+100),roads/(roads+100)]` =18; day `d/(d+100)`, week `w/(w+100)`, fraction of current20-second day, remaining benchmark time/3600 =4; current stage one-hot6; selected root control one-hot10; stalled-token count/4096 =1; four history-valid flags and four age features `age/(age+1)` =8; offer-pending flag1. Total6+18+4+6+10+1+8+1=54. At ROOT the selected-control one-hot is all zero. Do not include score as input in v1; score delta remains the reward. Use explicit bounded transforms, not running observation/reward statistics; no data-dependent normalization leakage.

`motorways`: visible records sorted by `(pending,start.y,start.x,end.y,end.x,id)`; rows `[start.x/49,start.y/29,end.x/49,end.y/29,pending,valid]`, zero padded to1,500. ID only stabilizes ordering, never a numeric input. Both active and visibly retiring links are included, enabling exact pair identity rather than arbitrary matching by nearby endpoints. Capacity is a conservative canvas-sized guard, not an action limit: if reached, fail schema validation and review capacity; never hide a legal motorway or drop records. If the viewer doesn't display a retiring link, exclude that hidden link from input and retain only genuinely visible endpoint/pending glyphs. No vehicle route arrays, Reservations, demand intervals, feasibility diagnostics, future ScheduledSpawns or raw RNG fields. Count unknown enum/colour/capacity overflow as schema errors, not silent clipping.

## 5. Architecture and objective

Custom MultiInputPolicy feature extractor, no recurrent state or pretrained encoder. Grid CNN: Conv2d(81,32,3,stride1,pad1), ReLU; Conv2d(32,64,3,stride2,pad1), ReLU; Conv2d(64,64,3,stride2,pad1), ReLU; AdaptiveAvgPool(4,7); flatten1792; Linear(1792,256),ReLU. Global MLP54→64,ReLU. Motorway shared row MLP6→32→32 with ReLU; masked mean and max pooling produce64 features (zeros for empty table, exclude padding). Concatenate384→256,ReLU. Separate actor256→128→1501 logits and critic256→128→1. Orthogonal initialization, hidden gain sqrt(2), actor-output .01, value-output1, all biases0. No soft route features, learned goals or masked-action penalties. Use float32, Adam eps1e-5, no AMP/compile. Why: preserves spatial layout with modest shared features and explicit motorway pairs; library has no direct recurrent MaskablePPO support [S2]. Widths are an engineering baseline, not proven optimal. Parameter count/shape are verified in the accompanying arithmetic checker, not a trained model.

Reward exactly `TripsCompleted_after - TripsCompleted_before` on every token transition, including any native instantaneous effects. No shaping, penalties, death bonus or artificial terminal payout. Raw episode sum must equal final score minus initial score. **gamma=1.0**, **GAE lambda=.95**. Rationale: in the finite benchmark the objective is undiscounted trips, and zero-time edit/operand counts should not discount them. This is a deliberate departure from default gamma, with greater variance/value-learning difficulty acknowledged. Lambda affects the estimator, not a new reward. Timeouts bootstrap; genuine game-over and the defined finite task horizon do not [S3]. Finite memory and GAE do not guarantee long-range construction will learn; low/zero trip learning is a result to diagnose, never permission to add bonuses.

## 9. Preflight gates, stopping and records

Before any learning: exact source/build handshake; schemas/shapes/finite values; revealed-state leakage audit; mask-query purity; test all legal neighbor directions including diagonals, water starts/extensions, circle footprint/activation, motorway edits and delayed refunds; sample1000 legal prefixes/actions over fixed test fixtures with zero physical rejections; replay land/bridge/roundabout/motorway/erase/weekly/wait traces; reward telescoping; no time on edits; wait20ticks with mid-offer early return; termination versus truncation bootstrap; stall guard; fresh initialization seed reproducibility; save/reload masked predictions; zero forbidden debug/planner commands. Fixtures are authored game-rule checks, no demonstration learning or final-test seed use.

During pilot: stop on nonfinite loss/gradient/value/probabilities, invalid masks or schema drift, masked-valid rejection, IPC/replay mismatch or source version mismatch. Integration failures are not low-scoring losses. Log approximate KL, clip fraction, valid-action entropy (also entropy/log(valid_count) when count>1), explained variance, policy/value losses, reward/score, no-ops/cancels, stage occupancy, complete edits, elapsed simulation and memory. KL epoch early stop alone is diagnostic; do not automatically change settings. Pilot pass: all integration gates pass, at least8full rollout updates complete with finite values, and one checked save/reload/replay. No minimum trip improvement required for integration pass; zero trips means learnability is unproven. If wall cap prevents gates, result incomplete, not pass. No continuation automatically authorized, and no shaping/planner substitution on poor learning.

Write configs before launch, immutable per-run IDs, initial/final/selected checkpoint hashes, source and build/protocol hashes, episode JSONL, PPO CSV and status heartbeat. Save latest every2048collected tokens at safe rollout boundaries and on interruption; retain periodic16384-token checkpoints and chosen best/final. Checkpoint writes use atomic replacement.
