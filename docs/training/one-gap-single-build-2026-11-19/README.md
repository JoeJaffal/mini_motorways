## Collection throughput check

Read-only inspection during the first ten completed CUDA rollouts found 20,480 attempts, 355.28 seconds of logged collection and 26.15 seconds of logged PPO updates. Collection is about 93% of those two measured phases and averaged 57.6 attempts per collection second. Median collection and update times were 35.12 and 2.60 seconds per rollout. Collection includes board reset, inference, native action and rollout checks. Individual costs were not timed in this review.

The code resets the 16 native hosts serially between groups of one-step games, fingerprints identical frozen policy weights multiple times per rollout, and prepares terminal observations and GPU tensors even though a terminal step has zero bootstrap value. Proposed first benchmark: parallelize independent resets, verify the weight fingerprint at rollout boundaries, and skip unused terminal work. Preserve native legality, seed streams and each attempt's binary reward. Compare identical seeded dry workloads and report attempts per second before selecting changes. A larger proposal is an in-memory one-step evaluator validated against native attempts, if profiling still points to host round trips. No runtime changes or competing benchmark ran during the pilot.

## Collection speed changes

Parallelized independent single-build resets using the existing worker pool, verify frozen weights once at each end of the rollout, and skip encoding, copying and transferring the ending board for one-step training. The ordinary environment step still returns the final observation for replay and evaluation. Each attempt retains its original seed, native mask and draw, binary reward, behavior log probability and zero terminal bootstrap.

Eight regression tests passed, including parity of actions, observations, values and returns against regular collection and an exact attempt cap spanning worker resets. Four low-priority CPU dry trials alternated between pre-change and optimized source, using the same native binary, four workers, seed 42 and 256 attempts per trial. Baseline collection was 6.74 and 6.65 seconds. Optimized collection was 3.57 and 3.69 seconds. Median collection fell from 6.69 to 3.63 seconds, a 1.84× speedup. Episode results matched after removing per-game wall times, and forward losses matched within 1e-7. All trial weights remained unchanged. This is a small CPU collection benchmark, and actual CUDA throughput with 16 workers remains unmeasured. [Benchmark and verification evidence](collection-speed-verification.json).
