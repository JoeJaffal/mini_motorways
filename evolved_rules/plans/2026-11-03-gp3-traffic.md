# gp-3: traffic moves (road only)

**Why.** gp-1 and gp-2 lose to traffic, not to a lack of tiles or connections (EXPERIMENTS.md). In gp-2's best rule (generation 14) on 1500–1519:

- About 70% of the stuck cars in lost games wait at junctions ("Crossing vehicle", "Approaching vehicle priority"), and about 27% at a shop's single car-park gate.
- About 6 of the failing colour's 11 stuck cars are within 3 tiles of the failing shop.
- About 40% of road cells are junctions, and the failing shop's doorstep (the cell outside its entrance) has 3.5 links on average.

The cause is the attach route: it joins a new house to the network cell nearest the shop, so junctions pile up at the doorstep that every car of that shop must cross.

**User decisions (2026-11-03):**
- No traffic lights, roundabouts or motorways in gp-3.
- The new moves go into the hand-built planner, and evolution learns when to use them.

## Decisions

| # | Decision |
|---|----------|
| G3-1 | **Clean routes** (`candidates.route_candidates(clean=True)`). One extra candidate per target with the separated cost model, plus charges for every junction link: 2.0 anywhere, plus 6.0 within 3 tiles of any doorstep. A junction link is a link added to a road cell that ends with ≥ 3 links. The old term only counted new junctions, so piling links onto an existing junction was free. Clean routes never end within 1 tile of a doorstep, except at a target shop's own doorstep when that doorstep has ≤ 1 link. The candidate is appended after the Phase 1 candidates, so with `clean` off the list is unchanged. |
| G3-2 | **Removal** (`removal_candidates`, `agent._remove_one`). A candidate is a plain road tile within 3 tiles of a doorstep that is a junction or is linked to a doorstep with ≥ 3 links. It is offered only if removing it keeps every house reaching every same-colour shop it reaches now. The policy's remove score must be > 0. At most 1 removal per decision, after routing. |
| G3-3 | **Traffic inputs.** Candidate inputs: `is_clean`, `near_shop_junctions`, `ends_near_shop`, `shop_doorstep_degree`, `shop_heading`, `shop_stuck`. Global inputs: `worst_doorstep_degree`, `most_stuck_near_shop`, `stuck_cars`. Removal inputs: `rm_*`. These read vehicle `stage`, `shopId`, `x`, `y` and `speed`: current-state fields, disclosed as extra fields beyond Mohammad's observation (PLAN decision 7). `route` and `returnRoute` stay excluded. |
| G3-4 | **Opt-in by policy attribute** (`clean_routes`, `removes`). Phase 1 rules and 3-tree GP texts play exactly as before. This is pinned by the Phase 1 fingerprints and by gp-2's best rule replaying two of its validation games (`tests/test_gp3.py`). |
| G3-5 | **Hand baselines.** `clean` (CleanHand): coverage, a clean route first, then a separated one. `cleanrm` (CleanRemoveHand): CleanHand plus removing a tile that feeds a doorstep with ≥ 3 links while ≥ 2 cars are stuck near that shop. |
| G3-6 | **4-tree individuals for gp-3:** priority, hold, upgrade, remove. A 4-tree text turns on `clean_routes` and `removes`. Seeds: hand, separated and clean as trees with remove = −1, plus gp-2's best with remove = −1. Same loop and stop rule as gp-2. |
| G3-7 | **Resuming gp-2.** gp-2 keeps running on the code it was started with (b8e82a0). If it stops, resume it from a worktree at b8e82a0: the terminal sets changed, so newer code would draw different random trees. Its best rule still plays identically on newer code. |

## Steps

1. Clean routes, traffic inputs, CleanHand. Measure on 1500–1519 against separated + coverage and against gp-2's best with and without clean routes.
2. Removal and CleanRemoveHand. Measure the same way.
3. 4-tree GP (gp.py, evolve.py seeds, CMA-ES layout), then review, then a smoke run.
4. When gp-2 has converged or been paused, launch `gp-3`.

## As built (after review, 2026-11-03)

- **Cars count by their cell.** Host car positions are cell centres (x + 0.5), so "stuck near a shop" uses `floor(x), floor(y)`. Comparing raw floats had shifted the 7×7 zone half a cell north-west.
- **Live links only.** `candidates.link_degree` ignores links to tiles pending removal. A doorstep that is being thinned no longer looks crowded, so removals do not stack. Junction counts and doorstep degrees use it.
- **Removal is cheaper.**
  - `removal_candidates` computes the pairs to keep once per call.
  - A 4-tree text whose remove tree is a constant ≤ 0 has `removes = False`, so it never computes removals; the seeds have remove = −1.
  - Clean routes cost about 35–40% more per `route_candidates` call (measured by the review).
- **`pending_refunds` is an input again,** because removals make it vary. Only `type_5` stays dropped.
- **Cache version `phase3-v2`.**
- **Known and harmless:** a stroke is rejected when a building spawns on a planned cell between planning and drawing. This happened in 206 of 16,578 gp-2 games and is unrelated to gp-3. The replay records the rejection, so verification still passes.
