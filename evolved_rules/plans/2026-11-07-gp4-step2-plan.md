# gp-4 Step 2: Evolving With Lights and Roundabouts — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run gp-4 evolution with a fifth tree, `place`, that decides where to put traffic lights and roundabouts, until the Phase 2 stop rule says it has converged.

**Architecture:** `gp.py` gains a `place` tree over the 15 `pl_*` placement inputs plus the global inputs. A 5-tree text turns placement on for both tools, the same way a 4-tree text turned on removal. `evolve.py` gains a `place_tree` switch that makes every individual 5 trees. Everything else is unchanged: the gp-3.3 loop (64 rule sets, racing 8 + 24 maps, hall of fame of 8 with a reference rule, probation, and the paired-t stop rule).

**Tech Stack:** Python 3, DEAP, the existing .NET headless host, pytest.

**Spec:** `evolved_rules/plans/2026-11-07-gp4-lights-roundabouts.md` (section "Step 2: gp-4 evolution", plus sections 3 and 4). Step 1 is done. Its hand-test results are in EXPERIMENTS.md, "2026-11-07: gp-4 step 1".

### Task 2: The `place` tree in `gp.py`

**Files:**
- Modify: `evolved_rules/gp.py`
- Test: `evolved_rules/tests/test_gp4_step2.py` (new)

**Interfaces:**
- Consumes: the 15 keys of `features.placement_features` (step 1): `pl_is_light`, `pl_is_roundabout`, `pl_degree`, `pl_doorstep`, `pl_cars_near`, `pl_stopped_near`, `pl_max_wait_near`, `pl_mean_wait_near`, `pl_dist_worst_shop`, `pl_worst_colour_stuck`, `pl_new_links`, `pl_joins_separated`, `pl_tiles_lost`, `pl_light_stock`, `pl_round_stock`.
- Produces:
  - `PLACEMENT_TERMS`: the 15 keys in that order.
  - `PLACE_TERMS = PLACEMENT_TERMS + GLOBAL_TERMS`.
  - `PLACE_SET = _make_set("place", PLACE_TERMS)`.
  - `ALL_TREE_NAMES`, `ALL_PSETS` and `ALL_TREE_TERMS` each gain a fifth entry. `TREE_COUNTS = (3, 4, 5)`.
  - `NEVER_PLACE = "-1.0"`.
  - `with_place(text: str, place: str = NEVER_PLACE) -> str`: a 3- or 4-tree text becomes a canonical 5-tree text. A 3-tree text first goes through `with_remove`. A 5-tree text is returned canonical and otherwise unchanged.
  - `random_individual(trees=5)`.
  - `TreePolicy`:
    - `.places_lights` and `.places_roundabouts` are both `trees == 5 and not _never_positive(place)`;
    - `.place(f) -> float` returns -1.0 for fewer than 5 trees and `-inf` for a non-finite score;
    - `.removes` is true for 4 or 5 trees when the remove tree is not a constant ≤ 0;
    - `clean_routes` defaults to on for 4 or 5 trees.

Scales for the new terminals use the existing powers of two:

| Terminals | Scale |
|---|---|
| `pl_is_light`, `pl_is_roundabout`, `pl_doorstep`, `pl_joins_separated` | FLAG |
| `pl_degree`, `pl_new_links`, `pl_tiles_lost` | DEGREE |
| `pl_cars_near`, `pl_stopped_near`, `pl_worst_colour_stuck`, `pl_light_stock`, `pl_round_stock` | COUNT |
| `pl_max_wait_near`, `pl_mean_wait_near` | SHORT_S |
| `pl_dist_worst_shop` | TILES |
