## 1. Goal, and what can honestly be guaranteed

**Goal:** a headline rule that is never worse than the previous version's best rule **L**, with the highest affordable chance of being measurably better.

**What is guaranteed, by construction:**
- **L stays the default.** The headline is L unless a challenger beats L in **one pre-registered, one-sided test on fresh maps**.
- **If the challenger fails that test,** the headline is L itself: literally the old rule, played by the old code.
- **If a challenger passes,** P(adopting a rule whose true mean is ≤ L's) ≤ 5%.

**What cannot be guaranteed: "measurably better".**
- Per-game SD is 265–400. Search alone has produced 0 validated gains on f34, while one planner fix gave +154.
- Realistically, P(headline ≠ L) is about 20–35%. Tell the user this up front.
- Runs end with status **`budget`**. Convergence is impossible by Nov 19.

## 2. The previous version L, and the headline protocol

### 2.1 L (pinned before handoff; recorded in HANDOFF.md §2)

**Rule.** L = the close-out policy with the highest mean on LA 5100-5299 (n = 200, gp6-v1 code). The candidates are cma-1 (3-tree = 5-tree, identical games), cma-6 mean, cma-6 best and gp-6 7fa4b2.
- **Tie rule.** If the leader's paired difference vs cma-1 3-tree is within 1 paired SE, L = cma-1 3-tree. When the tie rule decides, say so.
- **Played by old code only.** L is always played from a worktree of `gp6-final`, so it really is the previous version. It never goes through gp7 code paths.
- **x0's rule weights come from L** if L is a 3-tree weight text (cma-1, cma-6 mean or cma-6 best). If 7fa4b2 wins, a 29-node tree that the linear coordinates cannot express, x0 uses cma-1's weights. Say so in the write-up.

**Result (2026-11-14): L = cma-1 3-tree, 1021.2 trips** (`evolved_rules/seeds/gp7/cma1_3tree.txt`). It has the highest mean of the learned arms, so the tie rule was not needed. Next: cma-6 mean 1013.0 (−8.2, paired SE 19.2), cma-6 best 996.0, gp-6 7fa4b2 956.6. The average over the 5 learned arms is 1001.6. Full table in HANDOFF.md §2. x0's rule weights are therefore cma-1's.

### 2.2 Challengers, selection, single test

**Challengers (k ≤ 3):**
- **x0\***, the start point chosen by the screen (§5);
- **cma-7 final** (the in-bounds distribution mean at the last completed generation before T_stop);
- **gp-7 final**, if gp-7 ran.

**Freeze before validation.** Record the gp7 commit hash and each challenger's text hash. Validation and test are played with that exact commit. If the code must change afterwards, the headline stays L unless the test is re-run on unused maps.

**Validation selects only. This is its single sanctioned use.**
- Every challenger plays the validation maps 1550-(1549+n_val), paired by seed with L, which is pre-played.
- C\* = the challenger with the largest paired mean difference vs L. There is no p-value here.
- If every difference is ≤ 0, **the headline is L** ("no measurable improvement"). The test is then optional and descriptive.

**The test decides, once.**
- C\* plays 6100-(6099+n), paired with L, which is pre-played on 6100-6999.
- **n** = the largest multiple of 100 such that every seed in 6100-(6099+n) is complete for both C\* and L. Completeness alone decides n, never the results.
- **If n < 400 at T_freeze, the headline is L.**
- H0: μ(C\*) − μ(L) ≤ 0. Use a one-sided paired t at α = 0.05 as the decision statistic, and report the BCa 90% lower bound and Wilcoxon alongside it.
- **Adopt C\* only if it passes.** Nothing is changed after the test.

**Write the rule first.** `stats7.decide_headline()` implements this exactly and is committed before the first validation game. Its hash goes in the pre-registration (§8.4).

**EB is only for quoting numbers.** It never picks.

**Pairing across code versions is valid.** Games are deterministic per (code, simulator, text, seed), and the map is the pairing unit. L is played by gp6-final code and challengers by gp7 code, on the same simulator build.

### 2.3 Sizes and power

Test MDE, one-sided α 0.05, power 0.8: MDE = 2.487·SD/√n.

| Paired SD | n = 400 | n = 600 | n = 900 |
|---|---|---|---|
| 272 (measured: cma-6 mean vs cma-1) | 34 | 28 | 23 |
| 350 (rule with a changed planner) | 44 | 36 | 29 |

The test defaults to 900 if affordable and **never goes below 400**. When time is short, **cut training before the test**.

### 2.4 Secondary results (descriptive, Holm over 2)

- **gp-7 final vs cma-7 final**, two-sided, on the validation games. Both arms stop at the same T_stop on W/2 workers each. Report both cumulative ledgers next to the result, and say so if they differ by more than 10%. The curves against charged games (§8.3) show the comparison at equal games.

## 3. What gets built (gp7-v1)

### 3.1 The evolvable planner: C4-min, in both learners

**Principle.** The planner keeps its tools: A*, `draw` legality, stock checks, connectivity and the executor. Its hand-made choices become learned weights. The legacy candidates (attach, direct, separated, clean) stay on the menu.

**Cost head ("evo")** for a step u→n with ℓ = 1 or 1.414:

```
c(u→n) = max(floor(ℓ), ℓ·(w_paid·paid + w_reuse·(1−paid)) + w_step
                     + w_jn·[becomes_junction(u; prev,n) + becomes_junction(n; u) if n is a target]
                     + w_jl·junction_link + w_ns·junction_link·near_shop + w_for·foreign(n, colour)
                     + M[n])
floor(1) = _MIN_ORTH = 0.2;  floor(1.414) = _MIN_DIAG = 0.2621     (candidates.py:31-32)
M = w_car·cars_on + w_stop·stopped_on (+ gp-7 cost slot)            one 50×30 array per pass (colour-neutral)
```

- **Floors.** These are the constants the legacy octile heuristic uses, so A* stays admissible for every weight vector. Keep the **legacy heuristic unchanged**.
- **Exact arithmetic.** Add terms in the legacy order (base, u-junction, n-junction, foreign, then new terms), so costs are bit-identical at a legacy vector.
- **Where evo runs.** In each route pass of the build loop (agent.py:189-227), it runs on:
  - the top 8 legacy targets (attach targets);
  - each target-head pair. A connected pair searches toward the shop's doorstep cells (`s.outside`) only.
- **Candidates.** Evo candidates carry `is_evo = 1`. They are checked against the legacy `seen` set and appended after the legacy list.
- **When M is rebuilt.** After a pass that executed a route.
- **Cut:** turns, bridge and degree terms, heuristic scaling, the memo.

**Target head** over every (house, same-colour shop) pair:

```
t(h,s) = b_t + w_con·pair_connected + w_det·detour_ratio + w_dem·shop_demand(s) + w_over·shop_overcrowded(s) (+ gp-7 target slot)
picked = top M_eff pairs with t > 0;   M_eff = clip(floor(n_t), 0, 6)   (n_t learned)
```

- **`detour_ratio`.** The current network path length ÷ octile distance, 0 if unconnected. One BFS per shop, only for the 6 shops with the highest `overcrowded_for`, then demand.
- **`tiles_saved`.** For connected pairs, the network path length minus the new path length, in cells. It is a candidate feature.
- **No-op guards:**
  - An evo candidate must add at least 1 new link (path links minus existing links).
  - A connected-pair candidate also needs `tiles_saved ≥ 1`.
  - Each target-head pair is tried at most once per decision, using a **separate** `tried_target_pairs` set. `excluded_pairs` keeps its v6 meaning.

**Stress features (the ttf estimator is cut).** Only existing fields:
- `shop_overcrowded` / `worst_overcrowded` (`overcrowded_for`, features.py:408/477);
- `colour_margin` / `worst_margin`;
- `shop_demand`.

**New priority terms:** `is_evo`, `pair_connected`, `tiles_saved`.

**Light head.**
- `flags: clean=0 lights=0|1 roundabouts=0`.
- place = `if_gt(pl_is_light, .5, b_L + Σ p_n·s_n, −1)`.
- Removal stays off.

**Text format** (owned by gp.py). There are two optional trailer lines, in this order:
- `flags: clean=0 lights=1 roundabouts=0`
- a single-line `planner: <cost weights>; <target weights incl. n_t>; <slot trees>`

Floats are written in fixed repr, so `individual_text(individual_from_text(t)) == t`. Texts without the trailers canonicalise **byte-identically** to today. Unknown or out-of-order trailers raise ValueError. TreePolicy reads flags in place of the tree-count defaults (gp.py:442-444).

**Term tuples.**
- Keep `CANDIDATE_TERMS / GLOBAL_TERMS / OFFER_TERMS` and the v6 psets **unchanged**, so tune_cmaes still imports with DIM 81.
- Add `V7_*` tuples and v7 psets, computed in a separate feature dict only under `moves=v7`. `CODE_VERSION = "gp7-v1"`.

**Decision-record logging** (on request per game). Write `<run>/decisions/<hash>_<seed>.jsonl` with:
- the candidate feature matrices and the chosen index;
- the pair-term matrix and the chosen top pair;
- cell-map summaries;
- whether an evo route was built.

It is used in calibration, screen and trend-monitor games. A small script turns the records into **term spreads** (within decision for candidate terms, across decisions for global terms) and **new-route rates**.

### 3.2 The start point x0 ("Gentle": new routes on at a low rate)

- **Rule weights:** L's (§2.1) in live coordinates. Clean is off.
- **Cost head:** separated weights, with the reuse discount weakened (w_reuse = 0.5) and w_stop = 0.2.
- **Target head:**
  - w_det and w_over small and positive, w_con = 0;
  - n_t = 1.2, so at most 1 pair;
  - b_t set so a pair opens in **about 10% of decisions**.
- **Priority:** w_is_evo set so an evo route is **built in about 3–5% of decisions**. These are the "rate minimums".
- **Calibration:** live, at most 3 rounds × 8 games, with decision logging on. Use the calibration seeds in §7.
- **Never switched off.** If x0 is worse, its rates are reduced (§5).

### 3.3 cma-7: `evolve7.py`, a fork of `tune_cmaes.py` using pycma 4.5.0

**Engine.** pycma 4.5.0 with:
- `CMA_diagonal=True` (sep-CMA);
- `CMA_mirrors` (mirrored samples);
- `CMA_stds` (preconditioning).

Resume works by pickling the state, as tune_cmaes already does. The run folder is `output/evolved_rules/evolve7/<run>/`.

**Coordinates (about 80).**
- **Live rule weights:**
  - The 16 **priority** globals are folded into hold as hold_live[j] = hold[j] − prio[j]. This is exact, because a route is built only when the best priority ≥ hold.
  - The 16 **upgrade** globals are **dropped**. Every offer gets the same global term (agent.py:121), so they never change which offer is taken.
  - `pending_refunds` and `is_clean` are dropped.
- **Light head, cost head (9), target head (6).**
- **New priority terms (3).**
- **6 fixed templates:**
  - `mul(worst_overcrowded, path_cost_s)`
  - `mul(shop_overcrowded, tiles_saved)`
  - `mul(worst_overcrowded, road_stock)`
  - `mul(pl_stopped_near, worst_overcrowded)`
  - cost: `mul(gate(worst_overcrowded, θ_q75), stopped_on)`
  - target: `mul(shop_overcrowded, detour_ratio)`

  θ values are quantiles over the calibration games' decision records, frozen in the pre-registration. gate(x, θ) = 1[x > θ].
- **4 slot coordinates.** These are ordinary pycma coordinates in both arms, with the same CMA_stds entry, so ask() draws are identical in both arms. The decoder multiplies slot k by mask_k, which is 0 while the slot is empty, so an empty slot has no effect. cma-7 keeps all masks at 0. **Do not use `fixed_variables` or zero stds.**

**Identity gate (4).** L, converted by `linear.py` to live coordinates (planner off, templates, slots and new terms at 0) and written back as text, must give identical trips, seconds and commands to L on 8 maps. If L is 7fa4b2, run this on cma-1 instead.

**Scaling.**
- Each coordinate is weight = x·scale_i. Scale_i comes from the term spreads of the calibration and screen games (§3.1 logging): median 1, clipped to [0.1, 10].
- Biases, n_t, the cost-head weights and empty slots get scale 1.
- The scales are frozen in the pre-registration. Bounds are ±5 in x.
- **The search goes into the planner.** At the start, rule-weight coordinates get 0.25× the std of planner and new-term coordinates (via CMA_stds). sep-CMA adapts the stds afterwards; log the ratio each generation.
- **σ0 = 0.3** in scaled units. If more than 20% of gen-0 samples are cut early, or fewer than 25% build evo routes in ≥ 2% of decisions, halve σ0 once.

**Generation:**
- **Maps:** λ samples × m maps, fresh from 1-999 each generation and shared.
- **Early cut:** after 4 maps, a sample below 0.6 × the median 4-map mean stops.
- **Tell:** completed samples are ranked by their m-map mean. Cut samples rank below all completed ones, ordered by their 4-map mean. On resume, cut decisions are recomputed from the cached 4-map games.
- **Trend monitor:** the **in-bounds mean** (`es.boundary_handler.repair(es.mean)`) plays the generation's m maps. It is logged, never told to CMA.
- **Each generations.jsonl record** holds the mean's text, its hash, the population average and best of the sample means, and the cumulative ledger.
- **Removed from tune_cmaes:** per-generation validation on 1500-1549 and best-sample promotion. **The recommendation is always the in-bounds mean.**

**Stop.** `--stop-at <ISO timestamp with UTC offset>`, plus `<run_dir>/stop_at.txt` if present; the effective stop time is the earlier of the two. It is checked before each generation, and the run also stops if the last generation's wall time would cross it. The status is then `budget`. **To move T_stop earlier, write the file; no kill is needed.** Do not use `--max-hours`.

**Resume safety.** config.json records `git rev-parse HEAD` and CODE_VERSION. `--resume` refuses if either differs. Only `--workers` and the stop time may change on resume.

**Ledger.** Every distinct (text, seed) game the algorithm requests is charged. Resume replays are not charged.

### 3.4 gp-7-lite: `slots.py`, the GP part, including the planner

These are the same coordinates as cma-7, with **K = 4 live slots**: priority, hold, **cost** (a cell-map tree feeding M) and **target** (a pair-term tree).

**Slot trees:**
- at most 15 nodes, depth ≤ 4;
- primitives add, sub, mul, protected div, min, max, neg, `if_gt`, `gate(x, θ)`;
- constants change by Gaussian steps.
- **Terminals:**
  - cost slot (colour-neutral): cars_on, stopped_on, near_shop, worst_overcrowded;
  - target slot: pair_connected, detour_ratio, shop_overcrowded, shop_demand, octile distance;
  - priority and hold slots: that head's terms.

**Each epoch** (the end of every 5th generation after the fork):
1. **Propose** about 60 trees: subtree mutation, constant steps, the gate wrapper `mul(gate(stress, θ), F)`, and random depth-1–3 trees. Exact template copies are rejected.
2. **Zero-game screen** on the trend-monitor decision records.
   - A priority or hold proposal must change at least 3% of logged choices at w0, where w0 is the weight that changes 10% of them.
   - A target proposal must change the top pair in at least 3% of decisions.
   - A cost proposal must have within-map variance > 0 and |r| < 0.9 with stopped_on and cars_on.
   - Keep the top 2.
3. **Race** on 24 fresh probe maps: the mean plus 2 proposals at ±w0 = 120 games.
   - Accept if the paired difference vs the mean has one-sided p < 0.1. At most 2 per epoch.
   - **Insert** between tell() and the next ask():
     - set scale_k from the tree's spread on the logged records and set mask_k = 1;
     - set `es.mean[k] = clip(±w0/scale_k, −4.5, 4.5)`;
     - leave its variance;
     - checkpoint at once.
   - The races come out of gp-7's own budget.

**Cut:** Z_k freeing, archive, operator credit, two-stage races, crossover, bank refresh.

**Fork procedure:**
1. Commit the slot code with **CODE_VERSION `gp7-v2`**, tag it `gp7-fork`, and create a worktree `..\mm-gp7arm` at that tag.
2. Gate: a zero-game unit test shows that with every slot empty, gp-7 gives byte-identical ask() draws and decoded texts to cma-7. Then 8 games identical to the trunk.
3. Copy the trunk's checkpoint at a generation boundary into `output/evolved_rules/evolve7/gp-7/`, and start it with `--fork-from` (not `--resume`) from `..\mm-gp7arm`.
4. Restart cma-7 from its own frozen worktree with `--resume --workers W/2`.
5. Both arms are charged for the trunk.

## 5. The screen and the choice of x0\*

**Points**, each one weight vector in the shared coordinates, with L-based rule weights:
- **V0** = L (pre-played).
- **Gentle** = §3.2.
- **Fast:** no reuse discount (w_reuse = w_paid), any junction link +1.0, priority +1·`is_evo`.
- **Bypass:**
  - target w_con = 5, b_t = −5 − c, target template weight > 0, n_t = 3;
  - c chosen from the calibration records so that about the pairs with detour ≥ 1.33 at a shop in the top quartile of `overcrowded_for` are admitted;
  - Fast cost head.
- **Jam-avoid:** cost +0.5 per stopped car on a tile and +0.1 per moving car.
- **Lights:** `if_gt(pl_is_light, .5, pl_stopped_near, −1)`, plus an upgrade bonus of +0.8 on light offers.

**Size.** n_s maps each on 3300-(3299+n_s) (§6), chunked, with decision logging on.

**x0\* rule:**
- **Route part.** Take the point (Gentle, Fast, Bypass or Jam-avoid) with the largest paired difference vs V0, among the points meeting the §3.2 rate minimums. Use it if that difference is ≥ 0.
- **Otherwise,** use Gentle, with its rates halved if its difference is < −1 SE, or quartered if < −2 SE. **New routes are never switched off.**
- **Lights.** Add the light head if Lights' difference is ≥ 0.
- **Bug gate.** A point < −3 SE, or any rejected draw, triggers a 2 h bug check.
- **Quoting.** Never quote x0\*'s screen number. Validation re-measures it.

## 6. Budgets: every number comes from the measured throughput

**Definitions.**
- **R0** = games/h at W workers, from the timed worker sweep (HANDOFF §4).
- **R** = 0.85·R0/1.25, the planning rate for new-code play. Re-measure R each generation.

**Post-run games.** G_post = k·n_val + n_test, where k is the number of challengers. L and hand are pre-played.
- n_val = 200 if R ≥ 150, otherwise 150, and at least 100.
- n_test = the largest of {900, 600, 400} with G_post/R ≤ 14 h. If even 400 does not fit, go down one ladder rung.

**Run stop.** T_stop = T_freeze − G_post/R − 2 h. It moves only earlier.

**Screen.** n_s = the largest of {300, 200, 150, 100} with 5·n_s/R ≤ 7 h.

**Generation size.**
- cma-7 costs ≈ 0.92·λ·m + m games per generation. gp-7 costs that plus about 24 (races).
- **Games per arm** = R·(t_fork − launch) + (R/2)·(T_stop − t_fork), with t_fork = Nov 17 08:00. If gp-7 is dropped or not planned, it is R·(T_stop − launch) for cma-7 alone.
- Pick the largest (λ, m) in {(24,12), (16,12), (16,8), (12,8)} giving **≥ 25 generations per arm**. If (12,8) gives fewer than 15, drop gp-7.

**Worked example at R0 = 300:**
- **Post-run.** R ≈ 204, n_val = 200, n_test = 900 (G_post = 1,500 ≈ 7.4 h), so T_stop ≈ Nov 18 22:30.
- **Per arm.** Launch Nov 16 14:00 gives 18 h × 204 ≈ 3,670 before the fork, plus 38.5 h × 102 ≈ 3,930 after, about **7,600 games per arm**.
- **Generation size.** (24,12) costs about 277 games per generation, giving about 27 generations for cma-7 and about 25 for gp-7, so choose **(24,12)**.
- **L pre-play queue.** n_s + n_val + 900 + 900 hand ≈ 2,300 games (about 8 h). It runs during coding, while the CPU would otherwise sit idle.

### 8.2 Operations

- Long jobs run from frozen worktrees (§4), launched **detached** and watched by the watchdog (`--resume` only).
- Batteries are 100-seed chunks, run by restartable scripts.
- Power: never sleep. Pause Windows Update until Nov 20.
- `PYTHONHASHSEED=0`.
- **Never resume across code or simulator changes.** A **fork** into a new run folder under a new CODE_VERSION is allowed.

### 8.3 Reporting

- Every recap and table shows the **population average next to the best or the mean**.
- Curves use charged games on the x-axis.
- Report games, cache hits, CPU-hours and downtime per arm.
- Label runs `budget`.
